# S-PRIME ERP — 半導体精密機器 統合管理システム

**デモ：** https://sprimeerp.netlify.app

購買・出庫の起票から二段階承認、差戻し後の修正・再申請、分納入庫、検収・売上確定までを一人で体験できる、フロントエンド専用のERPデモです。実務で担当している製造業向けERP（生産・在庫・会計）の知識をもとに、業務フローと状態遷移を設計しました。

実API・データベース・本番認証は接続していません。データはブラウザ（localStorage）に保存されます。

## 開発について

企画、業務設計、状態遷移・画面設計、仕様策定、検証を担当しました。実装には生成AIツールを活用しています。

## デモの使い方

1. 任意の空でないID・パスワードでログインします。
2. 画面上部の「デモ用ロール切替」で操作者を切り替えます。
3. ダッシュボードの「あなたの未処理タスク」に、現在のロールで対応が必要な伝票が表示されます。

| ロール     | 担当者          | 主な操作                                           |
| ---------- | --------------- | -------------------------------------------------- |
| 申請者     | キム ヨンジョン | 購買・出庫依頼の起票と申請、差戻し後の修正・再申請 |
| 一次承認者 | 鈴木 花子       | 一次承認・否認                                     |
| 最終承認者 | 佐藤 健一       | 最終承認・否認                                     |
| 購買担当   | 山田 裕子       | 見積、発注、分納入庫、入庫完了、差戻し             |
| 検収担当   | 渡辺 涼介       | 検収                                               |
| 出庫担当   | 伊藤 真一       | 配送開始、出庫完了、売上確定、差戻し               |

ユーザーメニューの「デモデータ初期化」で、伝票とマスタを初期状態に戻せます。デモ用ロールは業務の流れを体験するためのもので、本番の認証・権限管理とは異なります。

## 業務の流れ

申請者が購買依頼を起票・申請すると、一次承認者・最終承認者の2段階で承認されます。承認後は購買担当が見積・発注を行い、入荷のたびに数量とLOT番号を分納入庫として記録します。全数量がそろうと入庫完了となり、検収担当の検収をもって完了します。

承認後、発注確定までに内容の見直しが必要な場合、購買担当は理由を添えて差し戻せます。起票者は同じ伝票番号のまま内容を修正して再申請でき、それまでの履歴はすべて残ります。一方、承認者による否認は最終判断のため、その伝票は再申請できません。

出庫依頼も同じ2段階承認を経て、出庫担当が配送開始（LOT番号を記録）、出庫完了、売上確定まで処理します。承認後に問題があれば出庫担当が差し戻し、起票者が修正して再申請します。

## 主な機能

- 伝票一覧、原材料・半製品購買、出庫管理、伝票の作成・修正
- 二段階承認、理由必須の否認・差戻し、修正開始と再申請
- 分納入庫（残数の範囲で数量入力、LOT番号の記録）と、全数入庫後の入庫完了・検収
- 全明細のLOT番号入力による配送開始、出庫完了、売上確定
- ダッシュボード：承認待ち・購買進行中・出庫進行中・安全在庫割れの件数、ロール別の未処理タスク、最近のワークフロー、伝票ステータス状況、安全在庫割れ警告（すべて伝票と品目マスタから算出）
- ワークフロー履歴と連動したヘッダー通知（未読表示・すべて既読・伝票への移動）
- 社員・品目・倉庫マスタの登録・修正・削除
- 入力チェック、確認ダイアログ、処理中表示、再読込後のデータ維持

## アーキテクチャ

状態遷移のルールは `src/lib/workflow.ts` の1か所だけで定義しています。画面の操作ボタン、ダッシュボードの未処理タスク、保存処理はすべてこの定義を参照するため、画面と処理の判定が食い違いません。

伝票は `src/services/mock-store.ts` のストアを通じて保存します。保存時には擬似的な待機（300〜500ms）を入れ、保存に成功してから画面に反映します。金額や件数は明細からストアで計算します。

`src/services/*.service.ts`、`src/types`、`src/hooks/api` は、将来のC# Web API連携に備えた構造で、現在のデモでは使用していません。

```text
画面 → ストア用フック → ローカルストア → localStorage
          伝票操作 → workflow.ts（遷移・実行可否・履歴）
将来：画面 → hooks/api → *.service.ts → api-client → C# Web API → PostgreSQL
```

## 起動・テスト・ビルド

Node.js 22 を推奨します（`.nvmrc`）。

```bash
npm install
npm run dev     # http://localhost:8080
npm test
npm run build
```

Node.js 25 以降でテストを実行する場合は、次のコマンドを使用してください。

```bash
NODE_OPTIONS=--no-experimental-webstorage npm test
```

テストでは、ワークフローの遷移ルール、ストアの保存処理、初期データの整合性を検証しています。
